Aevia

A personal platform on one server, built so that it can be rebuilt from Git.

Aevia runs my own services: workflow automation, monitoring, notifications, an AI gateway and a workspace for coding agents. It all lives on a single Hetzner server. Nothing is clicked together: OpenTofu creates the server, the firewall and the DNS records, k3s runs the workloads, and Argo CD applies whatever the repository says. If the server disappeared, the repository and one offline key would bring it back.

Principles

  • Git is the only source of truth. A push to the branch is the deploy; the cluster pulls, nobody pushes into it.
  • Deny first. Every namespace starts with no network access. Each connection that exists is written down and tested.
  • Agents stay in their lane. Code that models write runs in its own namespace. It can reach the AI gateway and one storage bucket, and nothing else inside the cluster. A test in CI proves it cannot reach the databases.
  • Secrets are encrypted in Git. SOPS and age; the cluster holds its own key, and I hold a copy offline.
  • One login. Cloudflare Access and Authentik sit in front of every private tool, with a one-time PIN as the way back in.
  • Restores are rehearsed. A database dump is destroyed and restored on every CI run, not only when something breaks.

At a glance

ServerOne Hetzner node, 4 vCPU and 8 GB, in Helsinki
Kubernetesk3s with Cilium (no kube-proxy, no bundled ingress)
DeliveryArgo CD, every service is an application; manifests are generated from one service catalog
EdgeCloudflare Tunnel (outbound only, no open web port) with Access and Authentik for sign-in
DataPostgreSQL, Redis, NATS and an S3-compatible store (SeaweedFS)
ObservabilityPrometheus, Grafana, Loki, Tempo and an OpenTelemetry collector
BackupsNightly, encrypted on the server before they leave it, stored in a separate Hetzner bucket
