Architecture

How a request travels, and what is kept apart from what.

The path of a request

A visitor reaches Cloudflare, which terminates TLS and, for private hosts, asks for a login first. The server has no open web port: a small agent inside the cluster holds an outbound tunnel to Cloudflare, and requests come in through it to Traefik, which routes by hostname to the right service.

What is kept apart

Namespaces are the unit of isolation, and every one begins with a policy that denies all traffic. Allowed paths are added one at a time. Applications may use the databases they need. Agents may call the AI gateway and a single storage bucket, and the databases are out of reach for them. A test starts a throwaway cluster with the same network rules and fails the build if an agent can open a connection to PostgreSQL.

Secrets and sign-in

Secrets are committed encrypted. Argo CD decrypts them inside the cluster with its own key, so the plain values never exist in Git or on a laptop that does not hold the key. Sign-in is layered: Cloudflare Access in front, Authentik as the identity provider behind it, and the tool's own login last. Grafana and Argo CD accept Authentik directly.

Failure and recovery

Databases are dumped every night, encrypted before they leave the server, and copied to a separate Hetzner bucket. A CI job drops a database, restores it from such a dump and checks that a test row survived. The server itself is replaceable: the repository describes it, and the offline key opens the secrets.
